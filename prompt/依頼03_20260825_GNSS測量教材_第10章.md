# 3. 第10章の位置付け

## 3.1 章タイトル

**ネットワーク型RTKとCLAS**

## 3.2 安定した章ID


## 3.3 前章・既習章からの流れ

第5章～第8章では、自前RTKについて、

```text
自分で基準局をつくる
  ↓
RTCM等を届ける
  ↓
基線解析・FLOAT → FIX
  ↓
現場で点検・採用判断
```

を学んだ。

第9章では、観測データと後処理解析、元期・今期、成果化を学んだ。

第10章では、利用者が現場に自前基準局を設置しない代表的な高精度リアルタイム測位として、

- ネットワーク型RTK
- VRS
- CLAS
- PPP-RTK

を扱う。

第4章ですでにネットワーク型RTKとCLASの概要比較を学んでいるため、第10章で同じ説明を繰り返さず、**外部情報がどこで作られ、どう届き、受信機がどう利用するか**を一段深く理解させる。

## 3.4 到達目標

第10章を学んだ後、学習者が次を説明できることを目標とする。

- 自前RTK、ネットワーク型RTK、CLASの違い
- ネットワーク型RTKが、単に遠くの電子基準点1局を自前基準局の代わりにする仕組みではないこと
- VRSの仮想基準点とは何か
- VRSでは移動局の概略位置を配信側へ送ることがある理由
- 配信側からVRS等のRTK用情報を受けても、移動局自身がGNSS観測を行う必要があること
- VRS直接観測方式では、仮想基準点と移動局の間の基線を求める考え方があること
- P1とP2で基準局やVRS仮想点が必ず同じとは限らないこと
- 実在基準局の切替とVRS仮想点の変更を区別すること
- CLASではセンチメータ級測位補強情報をみちびきL6Dから受信すること
- `L6D = P1までの距離を測る信号` ではないこと
- CLASは `ネットワーク型RTKのインターネットなし版` ではないこと
- CLASがPPP-RTKとして測位すること
- VRS等のRTKとCLASのPPP-RTKでは、高精度測位の考え方が同じではないこと
- ネットワーク型RTKとCLASの成果を比較するとき、FIXだけでなく座標の時点・高さ基準等も確認する必要があること

# 4. 第10章の中心メッセージ

章全体では、次の4点を軸にする。

## 4.1 現場基準局なしでも、仕組みは同じではない

> **ネットワーク型RTKとCLASは、どちらも利用者が現場に自前基準局を設置せず高精度測位できるが、基準・補強情報の作り方、届け方、測位方式は同じではない。**

特に次の誤解を防ぐ。

```text
CLAS
≠
ネットワーク型RTKのインターネットなし版
```

## 4.2 VRSは実在基準局1局ではない

> **VRSでは、周辺の基準局網の観測情報を利用して、移動局付近の仮想基準点に対応する情報を生成する。**

## 4.3 CLASはL6Dで補強情報を受けるPPP-RTK

> **CLASでは、みちびきL6Dから補強情報を受け取り、移動局自身のGNSS観測と組み合わせてPPP-RTK測位を行う。**

## 4.4 FIXだけで成果条件を判断しない

> **ネットワーク型RTKとCLASを比較するときも、FIXだけでなく、基準側情報、元期・今期、高さ基準、観測環境を確認する。**

# 8. カード1「ネットワーク型RTKとCLASは、自前RTKと何が違う？」

## 8.1 役割

第5章～第8章で学んだ自前RTKを基準に、第10章へ入る。

問い：

> 自前RTKでは、自分で基準局を準備しました。では、現場に自前基準局を置かないネットワーク型RTKとCLASは、何を使って高精度測位しているのでしょうか？

## 8.2 3方式比較

| 項目 | 自前RTK | ネットワーク型RTK | CLAS |
|---|---|---|---|
| 現場の自前基準局 | 利用者が設置 | 原則不要 | 不要 |
| 外部情報 | 自前基準局のRTCM等 | 配信サービスのRTK用情報 | CLAS補強情報 |
| 主な情報経路 | Ntrip等 / 別通信 | Internet / Ntrip等 | みちびきL6D |
| 測位の中心 | 基準局との相対測位 | VRS等のネットワークRTK | PPP-RTK |

## 8.3 最重要メッセージ

> **ネットワーク型RTKとCLASは、どちらも利用者が現場基準局を設置せず高精度測位できる。しかし、基準情報の作り方も、届け方も、受信機での測位の仕組みも同じではない。**

強調表示：

```text
CLAS ≠ ネットワーク型RTKのインターネットなし版
```

## 8.4 注意

VRS、PPP-RTKの内部説明はこのカードで先取りしない。

# 9. カード2「ネットワーク型RTKは何を基準にしている？」

## 9.1 問い

> 自前RTKでは、既知点Aに置いた基準局が位置の基準でした。では、現場に基準局を置かないネットワーク型RTKは、何を基準にしているのでしょうか？

## 9.2 中心図

カード内だけの静的模式図として、例えば次を示す。

```text
電子基準点等A ●             ● 電子基準点等B
          \                   /
           \                 /
            配信サービス側
            基準局網を利用
                 ↓
             RTK用情報
                 ↓
             移動局P1
                 ●
          ● 電子基準点等C
```

## 9.3 中心メッセージ

> **ネットワーク型RTKでは、利用者が現場基準局を設置する代わりに、電子基準点などの基準局網と配信サービスを利用する。**

次の誤解を防ぐ。

```text
ネットワーク型RTK
≠
遠くの電子基準点1局を、そのまま自前基準局として借りるだけ
```

また、配信情報だけでP1座標が完成するのではなく、**移動局P1自身もGNSS観測を行う**ことを明記する。

# 10. カード3「VRSとは？ ― 仮想基準点をつくる」

## 10.1 役割

ネットワーク型RTKの代表的な方式としてVRSを理解する。

VRS = Virtual Reference Station / 仮想基準点。

## 10.2 中心図

```text
電子基準点等の基準局網
      ↓
   配信側で処理
      ↑
P1の概略位置
      ↓
P1付近の仮想基準点データ
      ↓
     P1
```

必要に応じて、下部に次を追加する。

```text
仮想基準点 V ● ───── ● P1
                    基線
```

## 10.3 中心メッセージ

> **VRSでは、移動局の近くに物理的な基準局を新設するのではなく、周辺の基準局観測から仮想基準点に対応するRTK用情報を生成する。**

## 10.4 誤解防止

- VRS = 最寄りの電子基準点、ではない
- VRS仮想点には物理的なGNSS受信機が置かれているわけではない
- 仮想だから適当な架空データ、ではない
- 配信データだけでP1座標が決まるわけではない

## 10.5 次カードへの接続

> P1付近に仮想基準点を作るなら、配信側はP1がどこにいるか、どうやって知るのでしょうか？

# 11. カード4「VRSでは、P1の概略位置をどう伝える？」

## 11.1 中心概念

VRSでは、移動局側から配信側へ概略位置を送り、その位置に応じたVRS情報を受ける。

模式図：

```text
P1自身がGNSSで概略位置を得る
        ↓
P1 → 配信側
NMEA GGA等
「私はこのあたりにいます」
        ↓
配信側でP1付近のVRS情報を生成
        ↓
配信側 → P1
RTK用情報
        ↓
P1自身のGNSS観測と組み合わせる
```

## 11.2 最重要メッセージ

```text
配信側へ送る概略位置
≠
RTKで最終的に得たいcm級の成果座標
```

最初からcm級位置を送る必要がある、と誤解させない。

## 11.3 Ntripとの接続

第6章のNtripを再説明せず、VRSでは一方向受信だけでなく、位置情報を配信側へ送る場合があることを追加理解させる。

## 11.4 Drogger実機との接続

Drogger公式VRSページを補助リンクとして使い、次の存在を紹介してよい。

- 指定した位置を送信する
- 緯度・経度・楕円体高を指定する
- Waypointを指定する

ただし具体的な設定操作は実習編へ送る。

# 12. カード5「VRSでも基線を求めている？」

## 12.1 問い

> 自前RTKでは実在する基準局AとP1の基線を求めました。VRSでは基準点が仮想ですが、それでも基線を求めるのでしょうか？

## 12.2 扱う範囲

ここでは国土地理院資料にある**VRS直接観測方式**を代表例として扱う。

ネットワーク型RTKにはサーバ側で解析する構成等もあるため、

```text
すべてのVRS = 必ず移動局側で同じ基線解析をする
```

とは断定しない。

## 12.3 比較

```text
自前RTK
実在基準局A → P1

VRS直接観測
仮想基準点V → P1
```

表：

| 項目 | 自前RTK | VRS直接観測 |
|---|---|---|
| 基準側の点 | 実在する基準局 | 仮想基準点 |
| 基準側受信機 | 現場に実在 | 仮想点には存在しない |
| 基準側情報 | 実観測 | 基準局網から生成 |
| 移動局 | GNSS観測 | GNSS観測 |
| 相対位置 | A→P1 | VRS→P1 |

## 12.4 中心メッセージ

> **VRS直接観測では、仮想基準点の座標・観測情報と移動局自身のGNSS観測を用いて、仮想基準点からP1への相対位置を求める。**

第7章のFLOAT→FIXの内部説明は繰り返さない。

# 13. カード6「P1とP2で基準局は変わる？」

## 13.1 中心の問い

> P1を観測したあとP2へ移動しました。ネットワーク型RTKでは、P1とP2で同じ基準局を使っているのでしょうか？

## 13.2 中心メッセージ

> **必ず同じとは限らない。サービス方式、再接続、送信位置等によって、実在基準局やVRS仮想点が変わる場合がある。**

ただし、

```text
測点が変わった
→ 必ず基準局が変わる
```

とは説明しない。

## 13.3 静的2ケース

### ケースA 同じ基準側

```text
P1
VRS-A → P1

P2
VRS-A → P2
```

### ケースB 基準側が変わる

```text
P1
VRS-A / 基準局A
  ↓
Ntrip切断・再接続等
  ↓
P2
VRS-B / 基準局B
```

## 13.4 実在基準局とVRSを区別

```text
自動基準局選択サービス
基準局A → 基準局B

VRS
仮想点VRS-A → 仮想点VRS-B
```

同じ話として扱わない。

## 13.5 Droggerとの接続

Drogger公式資料に基づき、次を紹介する。

- 現在位置から基準局を自動選択するサービスでは、接続開始位置の違い等で異なる基準局が選ばれる場合がある
- 常に同じ位置を送信し、基準局選択を固定する考え方がある
- 「セッション全点で同一基準局座標が必要」をONにすると、VRS等で仮想点が変わった場合にエラーとできる

具体操作・出力確認は実習編へ送る。

# 14. カード7「CLASはどこから補強情報を受ける？」

## 14.1 中心図

```text
電子基準点データ等
       ↓
CLAS補強情報を生成
       ↓
     みちびき
       ↓
      L6D
       ↓
CLAS対応受信機 P1
       ＋
P1自身のGNSS観測
       ↓
   高精度測位
```

## 14.2 中心メッセージ

> **CLASでは、電子基準点データ等から作られたセンチメータ級測位補強情報を、インターネットではなく、みちびきL6Dから受信して利用する。**

## 14.3 ネットワーク型RTKとの比較

| 項目 | ネットワーク型RTK | CLAS |
|---|---|---|
| 外部情報 | RTK用情報 | センチメータ級測位補強情報 |
| 主な経路 | Internet / Ntrip | みちびきL6D |
| Ntrip | 代表的に利用 | 高精度測位自体には不要 |
| 携帯通信 | 通常必要 | 高精度測位自体には不要 |
| 受信機 | RTK対応 | L6D / CLAS対応が必要 |

## 14.4 誤解防止

```text
CLAS
≠
みちびき1機だけで位置を測る
```

```text
L6D
≠
P1までの距離を測るための測距信号
```

通常のGNSS観測とCLAS補強情報を組み合わせることを示す。

## 14.5 携帯圏外

携帯圏外でCLASが有力な選択肢になることを示してよい。

ただし、

```text
携帯圏外
→ CLASなら必ず測れる
```

とはしない。

上空視界、L6D受信、衛星配置、マルチパス、搬送波位相の連続性等も関係する。

# 15. カード8「CLASのPPP-RTKとは？」

## 15.1 問い

> 自前RTKやVRSでは基準点とP1の相対位置を求めました。CLASでも、どこか1つの基準局からP1までの基線を求めているのでしょうか？

## 15.2 中心メッセージ

> **CLASのPPP-RTKでは、特定の1基準局からP1までの基線を中心に考えるのではなく、衛星軌道・時計・バイアス・大気等の補強情報とP1自身のGNSS観測を利用して高精度な位置を求める。**

## 15.3 補強情報の例

細かなメッセージ番号の暗記は不要。

代表例として、

- 衛星軌道
- 衛星時計
- 信号バイアス
- 電離層
- 対流圏

等を示す。

## 15.4 PPP-RTKの説明粒度

PPP = Precise Point Positioning / 精密単独測位。

ただし、

```text
PPP
=
スマートフォン等の通常の単独測位
```

とはしない。

教材では、

> 近傍の1基準局との基線を直接中心にするのではなく、精密な衛星・大気等の補強情報を受信機側で利用して高精度位置を求める

と理解させる。

CLASがPPP-RTKであることは、QZSS公式CLASLIBおよびDrogger公式資料に基づく。

## 15.5 FIXの扱い

第7章の整数アンビギュイティ詳細は繰り返さない。

Drogger等ではCLAS PPP-RTKでもFIX状態を扱うが、

```text
同じ FIX 表示
=
同じ測位方式
```

ではないことを強調する。

## 15.6 VRSとの比較

| 項目 | VRS | CLAS |
|---|---|---|
| 基準の中心 | VRS仮想基準点 | 特定1基準点を中心にしない |
| 相対基線 | VRS直接観測ではVRS→P1 | 基線を中心に考えない |
| 外部情報 | VRS側RTK用情報 | 衛星・大気等の補強情報 |
| 情報経路 | Internet / Ntrip等 | みちびきL6D |
| 高精度測位 | RTK | PPP-RTK |

# 16. カード9「ネットワーク型RTKとCLAS、現場ではどう使い分ける？」

## 16.1 役割

第10章の総まとめ。

方式選択だけでなく、成果比較時の確認まで一本につなぐ。

## 16.2 現場で確認する主な項目

| 確認項目 | ネットワーク型RTK | CLAS |
|---|---|---|
| 情報経路 | Internet / Ntrip | みちびきL6D |
| 基準側 | 実在基準局 / VRS等 | 特定基準局との基線を中心にしない |
| 特に見るもの | 通信、接続先、基準局・VRS | 上空視界、L6D受信、収束・FIX |

## 16.3 現場ケース

### 携帯通信が安定

ネットワーク型RTKを利用しやすい。

ただし、接続先・基準局・VRS等を確認する。

### 携帯圏外・上空視界良好

CLASが有力な選択肢になる。

ただし、L6Dを含むGNSS受信条件が必要。

## 16.4 成果比較前チェック

ネットワーク型RTKとCLASで同じP1を観測した結果を比較するとき、FIXだけで判断しない。

表示例：

```text
□ 測位状態は適切か
□ 同じ測地系か
□ 同じ座標の時点（元期 / 今期）か
□ 高さの種類・基準は同じか
□ 使用した基準・補強情報は何か
□ 観測環境に問題はないか
```

## 16.5 元期・今期

第9章の内容を再説明せず、第10章の方式比較に接続する。

Drogger公式の整理では、

- RTK / スタティックは相対測位で、移動局の期は基準局に与えた座標の期に従う
- データサービス会社では通常元期座標を使用するという説明がある
- CLASによる測位は今期座標

とされている。

ただし、教材では、

```text
すべてのネットワーク型RTKサービスは必ず元期
```

と一般化しない。

中心表現は、

> **ネットワーク型RTKの座標時点は基準側座標・サービス仕様を確認し、CLASとの比較では同じ時点へそろっているか確認する。**

とする。

## 16.6 高さの注意

国土地理院は2025-04-01の標高成果改定に伴い、電子基準点からの補正情報を利用するネットワーク型RTK-GNSS等で、改定前後の高さ情報が混在しないよう注意を示している。

教材では年度固有の改定内容を暗記させるのではなく、

> **高さ比較時には、使用している成果体系・補正情報・高さ基準を確認する。**

とする。

## 16.7 総まとめ

> **① ネットワーク型RTKは通信環境と基準局・VRSを確認する。**

> **② CLASは携帯通信を必要としないが、上空視界とL6Dを含む受信条件が重要。**

> **③ 両方式の成果を比較するときは、FIXだけでなく元期 / 今期・高さ基準・基準 / 補強情報までそろえて確認する。**

# 31. 技術表現上の重要な注意

## 31.1 ネットワーク型RTK

`ネットワーク型RTK = 最寄り電子基準点1局を借りる` としない。

基準局網と配信サービスを利用する方式として説明する。

## 31.2 VRS

`VRS = 実在する電子基準点` としない。

`VRS = 適当な架空点` ともしない。

## 31.3 GGA / 概略位置

`GGAで送る位置 = 最終成果座標` としない。

`Ntripは常にGGA必須` ともしない。

VRS等、位置情報を必要とするサービスで用いられることを中心にする。

## 31.4 VRS基線

カード5とQ5は、**VRS直接観測方式**の代表例であることを明確にする。

ネットワークRTKのすべてのサービス・VRS構成について、受信機側で同一の基線解析を行うと断定しない。

## 31.5 基準局変更

`P1→P2へ移動すると必ず基準局が変わる` としない。

`ネットワーク型RTKは必ず同じ基準局` ともしない。

## 31.6 CLAS

次の誤解を防ぐ。

```text
CLAS = インターネットなしVRS
CLAS = みちびきだけで測位
L6D = 測距信号
CLAS = 最寄り電子基準点との通常RTK
```

## 31.7 PPP-RTK

`PPP = 普通の単独測位と同じ` としない。

`PPP-RTK = VRSの別名` としない。

## 31.8 FIX

```text
同じFIX表示
≠
同じ測位方式
```

また、

```text
FIX
≠
成果座標が必ず正しい / 両方式で必ず一致
```

を維持する。

## 31.9 元期・今期

ネットワーク型RTKの座標時点は基準側座標・サービス仕様に関係する。

`ネットワーク型RTK = 必ず元期` と一律化しない。

Drogger公式の「通常データサービス会社は元期座標」「CLASは今期座標」は、Droggerでの実務理解を助ける公式例として扱う。

## 31.10 高さ

2025年の標高成果改定は、成果比較時に高さ基準・補正情報を確認する必要性を示す実例として扱う。

年度固有の改定内容や数値を暗記問題にしない。
